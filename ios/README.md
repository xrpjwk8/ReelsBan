# ReelsBan for iPhone

iOS 26.5 이상을 대상으로 하는 Screen Time 기반 개발 버전입니다. 선택한 여러 앱에 각각 하루 사용 시간 한도를 적용합니다. 기본 한도는 앱마다 30분이며 앱 간 사용 시간을 합산하지 않습니다. 인스타그램을 선택하면 릴스·피드·DM을 포함한 앱 전체 사용 시간을 집계합니다. 앱의 내부 화면이나 영상 개수를 읽지 않습니다.

## 동작

1. ReelsBan에서 **Screen Time 접근 허용**을 누르고 개인 사용자 권한에 동의합니다.
2. 권한이 승인되면 **접근 허용 완료**가 표시되고 앱 선택 화면이 자동으로 열립니다. 이미 승인한 경우에는 **제한할 앱 선택**을 누릅니다. 인스타그램·유튜브 등 원하는 앱들을 선택하고 **완료**를 누릅니다. 카테고리와 웹사이트는 선택할 수 없습니다. Apple의 비공개 앱 토큰을 사용하므로 인스타그램을 자동 선택하거나 식별하지 않습니다.
3. 앱 선택을 완료하면 하루 제한 스위치가 켜집니다. 각 앱의 분 단위 한도(앱마다 기본 30분, 1~480분)를 정한 뒤 **오늘의 약속 저장**을 누릅니다. 저장 성공 시 **저장 완료** 팝업이 뜹니다. 실패하면 성공 팝업 없이 오류를 안내합니다.
4. 시스템이 하루 누적 사용 시간의 임계치 이벤트를 전달하면 해당 한도에 도달한 앱만 차단합니다. 이벤트 전달 지연이 있을 수 있습니다.
5. 차단 화면의 **설정한 사이트 열기**를 누르면 iOS가 ReelsBan을 열고 앱 안의 Safari 화면에서 저장한 사이트를 표시합니다. 사용자 탭 없이 다른 앱을 강제로 열지는 않습니다.
6. 기기의 현지 날짜 기준 일일 스케줄이 다시 시작되면 제한이 초기화됩니다. 야간에 기기를 사용하지 않은 경우 시스템 콜백은 다음 사용 시 전달될 수 있습니다. ReelsBan을 다시 열 때도 이전 날짜의 차단을 정리합니다.

오늘의 이전 사용 시간도 집계하도록 `includesPastActivity: true`를 사용합니다. 실제 집계와 이벤트 전달은 Screen Time이 담당합니다. 각 앱 카드에는 오늘의 Screen Time 사용 시간과 집계 갱신 시각을 표시합니다. 실시간 초시계가 아니며 집계 반영이 지연될 수 있습니다. 앱으로 복귀하거나 **오늘 사용 시간 새로고침**을 누르면 다시 조회합니다. iPhone 기록을 대상으로 하며 기기 간 공유 설정에 따라 다른 iPhone 사용량도 포함될 수 있습니다. 조회 결과가 없으면 기록 없음으로 표시합니다. 공고 열기는 차단을 해제하지 않습니다. 앱에서 제한을 끄고 저장하면 차단이 해제됩니다. 자기 관리용 권한이므로 사용자가 권한을 취소하거나 앱을 삭제해 제한을 해제할 수 있습니다.

기본 목적지는 [맥도날드 공고](https://mcdonalds.recruiter.co.kr/career/jobs/130416)입니다. 홈의 **공고 보기 · 이동 사이트 설정**을 누르고, 공고 화면 상단 **이동할 사이트 설정**을 펼쳐 http:// 또는 https:// 주소를 저장할 수 있습니다. 모든 제한 앱에 같은 주소를 사용합니다. 한도 도달 후 차단 화면에서 열린 사이트에는 주소 설정 UI를 표시하지 않습니다. 주소 변경은 홈의 **공고 보기 · 이동 사이트 설정**에서만 가능합니다. **맥도날드 기본값**을 누르거나 빈 주소를 저장하면 기본 공고로 돌아갑니다. 잘못된 주소는 저장하지 않고 기존 주소를 유지합니다. 위치를 수집하거나 공고의 모집 상태를 확인하지 않습니다.

## 이름 설정

홈의 **나를 부를 이름**에 이름이나 별명을 입력하고 **이름 저장** 또는 **오늘의 약속 저장**을 누릅니다. 오늘의 약속 저장 시 이름도 함께 저장됩니다. 예를 들어 `버러지`를 저장하면 다음 한도 도달 화면에 **버러지님, 오늘의 한도에 도달했어요**가 표시됩니다. 최대 20자이며, 빈칸으로 저장하면 기존 문구를 사용합니다. 이름은 App Group의 공유 파일에 원자적으로 저장되며 차단 화면에서 직접 읽습니다. 기존 UserDefaults 이름도 호환해서 읽습니다. 이름 설정은 앱별 한도나 집계에는 영향을 주지 않습니다. 이미 표시된 차단 화면은 iOS가 캐시할 수 있으므로 다음에 화면이 구성될 때 반영됩니다.

## 잠금 암호가 없는 경우

Apple의 개인용 Family Controls 권한에는 **아이폰 잠금 암호**가 필요합니다. 이 오류가 나면 앱에서 한글 안내와 **설정 → Face ID 및 암호(또는 Touch ID 및 암호) → 암호 켜기** 경로를 보여줍니다. 암호 설정 후 접근 허용을 다시 누르면 됩니다. 스크린 타임용 별도 암호나 Apple 계정 비밀번호가 아닙니다. 기기 잠금 암호를 설정하지 않으면 사용 시간 제한은 이용할 수 없지만, 사이트 주소 설정과 열기는 사용할 수 있습니다.

## 개발 환경과 설치

- iOS **26.5 이상**이 설치된 실제 iPhone
- **iOS 26.5 이상 SDK**가 포함된 Xcode
- Family Controls capability를 사용할 수 있는 Apple Developer 팀 및 서명 설정
- 프로젝트 재생성 시에만 XcodeGen 필요. 생성된 `ReelsBan.xcodeproj`를 바로 열어도 됩니다.

최소 버전은 [ShieldActionResponse.openParentalControlsApp](https://developer.apple.com/documentation/managedsettings/shieldactionresponse/openparentalcontrolsapp)의 도입 버전인 iOS 26.5입니다. 초기 개발 때는 구형 SDK로 일부 컴파일만 확인했지만, 현재는 **Xcode 27 / iOS 27 SDK에서 최신 API를 포함한 전체 무서명 빌드를 확인했습니다.** 실제 기기의 권한 승인·차단·공고 전환은 별도 검증이 필요합니다.

1. `ios/ReelsBan.xcodeproj`를 엽니다.
2. `ios/Config/Signing.local.xcconfig.example`을 같은 폴더의 `Signing.local.xcconfig`로 복사하고 `YOUR_TEAM_ID`를 본인의 개발 팀 ID로 바꿉니다. 이 로컬 파일은 Git에서 제외되고 다섯 타깃이 같은 팀을 사용합니다. Signing & Capabilities에서 팀이 올바른지 확인합니다.
3. 번들 ID를 팀에서 소유한 고유 값으로 변경합니다. 확장 ID는 앱 ID 뒤에 `.monitor`, `.shieldconfiguration`, `.shieldaction`, `.usagereport`를 붙인 형태로 유지합니다.
4. 다섯 타깃 모두 **Family Controls**를 설정합니다. 기존 앱·모니터·차단 화면·차단 동작 네 타깃은 동일한 **App Groups**도 설정합니다. 새 **UsageReport** 타깃은 보고서를 자체 표시하므로 App Group을 사용하지 않습니다.
5. 프로젝트의 `REELSBAN_APP_GROUP` 빌드 설정을 등록한 App Group ID로 변경합니다. 기본값 `group.com.reelsban.shared`는 개발용 자리표시자입니다. Info.plist와 entitlement는 이 값을 공통으로 사용합니다.
6. 실제 iPhone을 연결하고 `ReelsBan` 스킴을 실행합니다.

`project.yml`에도 같은 식별자를 반영해야 XcodeGen 재생성 시 변경이 유지됩니다. 개인 개발 팀 정보·인증서·프로비저닝 파일은 저장소에 넣지 않습니다. App Store/TestFlight 배포에는 앱과 확장의 [Family Controls 배포 권한](https://developer.apple.com/documentation/familycontrols/requesting-the-family-controls-entitlement) 승인이 필요합니다.

## 구성

| 타깃 / 폴더 | 역할 |
|---|---|
| ReelsBan / App | 권한, 앱 선택, 한도 설정, 공고 표시 |
| ActivityMonitor / Monitor | 하루 스케줄, 임계치 수신, 차단·해제 |
| ShieldConfiguration | 흑백 차단 화면 |
| ShieldAction | 공고 버튼 요청 저장 후 관리 앱 열기 |
| UsageReport | 앱별 오늘 사용 시간 보고서 표시 (원본 사용량은 메인 앱이나 공유 저장소로 내보내지 않음) |
| Shared | App Group 설정·차단 기록, 지정 ManagedSettings store |
| Policy | 날짜·설정 세대에 따른 차단 판단과 테스트 |

설정 변경마다 모니터링 이름에 새 revision을 사용해 이전 설정의 지연된 콜백이 새 설정을 차단하지 않도록 합니다. 등록 실패 시 이전 설정을 복원합니다. 같은 날 동일 설정 저장은 기존 모니터링을 유지합니다. 앱별로 토큰 하나만 포함하는 별도 이벤트를 등록하고, 차단 기록도 앱별로 분리합니다. 다른 앱 설정을 바꾸더라도 한도가 그대로인 앱의 당일 차단은 유지합니다. 기존 단일 앱 설정은 읽기 시 앱별 설정으로 변환합니다. 공고 요청은 한 번만 소비하고 2분이 지난 요청은 버립니다.

설정과 차단 기록은 기기의 App Group UserDefaults에, 이름은 App Group 공유 파일에도 저장합니다. 별도 서버, 계정, 분석 SDK는 없습니다. 공고를 열 때 해당 외부 웹사이트에 접속합니다. Chrome 버전과 설정·사용량을 동기화하지 않습니다.

## 검증 명령

저장소 루트에서:

```sh
swift test --package-path ios/Policy
xcodegen generate --spec ios/project.yml
./ios/build.sh
```

`build.sh`는 SDK가 26.5 미만이면 원인을 출력하고 중단합니다. 서명 없는 소스 빌드이며 기기에 설치할 수 있는 배포 파일을 만들지는 않습니다.

구형 SDK에서 최신 API 호출 한 줄을 제외한 컴파일 검증만 하려면:

```sh
./ios/build.sh --smoke-test
```

이 모드는 배포 대상만 17.4로 임시 낮추고 `REELSBAN_SDK_SMOKE_TEST`를 사용해 앱 열기 응답을 `.close`로 대체합니다. **실제 제품 동작 검증이나 배포용이 아닙니다.** 해당 플래그를 Release에 적용하면 컴파일 오류를 발생시킵니다. 정식 프로젝트의 최소 버전은 26.5를 유지합니다.

## 사용량 표시와 새 확장 서명

UsageReport 확장이 앱에 포함되어야 사용 시간이 표시됩니다. Xcode에서 새 타깃에도 개발 팀과 Family Controls capability가 적용되었는지 확인하고, TestFlight/App Store 배포 시 새 확장의 배포 권한도 준비하세요. 시뮬레이터에는 실제 사용 기록이 없으므로 조회 화면은 실기기에서 확인해야 합니다.

## 실기기 검증 체크리스트

시뮬레이터와 순수 정책 테스트만으로 Screen Time 동작을 검증할 수 없습니다.

- 저장 성공·동일 설정 저장·제한 끄기 각각에서 저장 완료 팝업, 저장 실패 시 성공 팝업 없음
- 각 앱 사용 후 오늘 사용 시간 표시 / 새로고침·앱 복귀·날짜 변경 시 갱신
- 권한 승인·거부·취소 후 올바른 상태 및 오류 안내
- 여러 앱 선택 후 각기 다른 한도 지정 / 카테고리·웹사이트 선택 거절
- 인스타그램 한도 도달 시 유튜브는 계속 사용 가능, 이후 유튜브도 한도 도달하면 둘 다 차단
- 사용자 사이트 주소 저장·재실행 후 유지 / 잘못된 주소 거절 / 맥도날드 기본값 복원
- 잠금 암호 없는 기기의 한글 안내 및 암호 설정 후 재시도
- 1~2분 한도로 실제 사용 후 차단되는지 확인(이미 사용한 시간 포함)
- 앱 종료 상태에서도 DeviceActivity 임계치 콜백이 차단 적용
- 차단 화면 공고 버튼 → 앱 실행 → 공고 표시(앱 종료·백그라운드 각각)
- 공고 닫은 후 인스타그램 차단 유지
- 설정을 그대로 저장해도 기존 차단 유지
- 한도를 높이거나 낮췄을 때 오늘 누적 사용량 기준으로 재평가
- 제한 끄기 저장 시 차단 해제, 다시 켜면 당일 사용 시간 포함
- 실제 자정 경과 후 새 일일 한도 적용(시계 변경만으로 대체하지 않기)
- 재부팅·시간대 변경·기기 간 Screen Time 공유 설정별 집계 범위 확인

현재 확인: 순수 정책 테스트 6개 통과, 초기 설정 화면 시뮬레이터 표시 확인, Xcode 27 / iOS 27 SDK에서 전체 무서명 빌드 통과. 권한 상태 구독, 승인 후 앱 선택 자동 전환, 선택 취소·완료, 저장된 제한 상태 안내를 추가했습니다. 앱별 독립 차단·날짜 초기화·웹 주소 검증을 테스트했습니다. 수정된 다중 앱 선택·각 앱의 실제 시간 집계·암호 안내·사이트 전환은 아이폰에서 확인해야 합니다.
